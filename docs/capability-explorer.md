# Capability explorer

Generated by `kicadai capability docs`. Do not edit the inventory by hand.

Supported front-door workflows and existing generation profiles; not every experimental command, not installed-tool detection, not hardware approval.

## component-self-test

Revalidate quarantined component evidence and execute small candidate-bound regression circuits.

Evidence level: `quarantined_software_regression_not_promotion`. Evidence: `docs/project-review-and-integration.md`.

Input contract: `kicadai.component-self-test-request.v1`.

Supported bounds:

- 1–8 fixtures, <=16 components/32 nets per fixture; 1–8 source documents <=2 MiB each
- Explicit DC, <=256 AC points or <=1024 transient steps; allowed analyses must match candidate provenance

Required tools:

- indexed KiCad symbol and footprint libraries; existing candidate and immutable source documents; no provider

Limits and acceptance requirements:

- Does not add parts to the supported catalog, grant independent approval, run physical validation or bypass promotion gates
- Fixtures must execute candidate components; assertions are authored expectations, not manufacturer-model certification

```sh
kicadai --request candidate.json --file self-test.json --symbols-root /libraries/symbols --footprints-root /libraries/footprints --output ./out/component-tests component self-test
```

## divider

Confirmed, offline divider schematic and explanatory report.

Evidence level: `analytical_and_internal_checks; native_erc_opt_in`. Evidence: `specs/schematic-first-workflow/acceptance.json`.

Input contract: `kicadai.schematic-assistant.v1`.

Supported bounds:

- Input: 0.1–24 V; R1/R2: 1000–1e+06 ohms
- Load: 1000–1e+09 ohms, or 0 for explicitly unloaded (not shorted)
- Predicted resistor dissipation <= 0.125 W (workflow budget, not a qualified part rating)

Required tools:

- none for internal checks; installed kicad-cli for opt-in ERC/preview

Limits and acceptance requirements:

- Ideal passives and zero-impedance source; no physical validation or PCB output
- Confirmation hash detects changed specs; it is not engineering approval

```sh
kicadai --output ./out/divider schematic example divider
kicadai --output ./out/session schematic new
```

Input contract: `kicadai.schematic-review.v1`.

Supported bounds:

Required tools:

Limits and acceptance requirements:

- Not a circuit repair, functional performance assessment or hardware approval

```sh

kicadai --target ./out/review review verify
```

## generation/generic-circuit-v1

Existing generic generation contract.

Evidence level: `declared_contract_requires_per_run_acceptance`. Evidence: `docs/ai-generation.md`.

Input contract: `kicadai.circuit-graph.v1`.

Supported bounds:

- catalog-resolved components, packages, symbols, and pin functions
- limits: 512 components, 1024 nets, 512 endpoints per net
- explicit multi-unit component identities and required power units
- relative schematic layout intent and bounded PCB placement regions
- deterministic placement and ordered routes for graph shapes

Required tools:

- catalog resolution; native KiCad for native acceptance; provider only when explicitly selected

Limits and acceptance requirements:

- ambiguous catalog resolution, unsupported pin functions, and incomplete graph intent fail closed
- not free-form or guaranteed for arbitrary dense, high-speed, RF, or analog circuits
- routing is bounded and does not implement general rip-up-and-reroute
- analog performance, thermal behavior, and fabrication suitability require explicit evidence or review
- strict graph or request validation and trusted catalog resolution
- schematic electrical and readability checks
- required-net connectivity and route completion
- writer correctness and normalized round-trip checks
- KiCad ERC and DRC when the requested acceptance requires them

```sh
kicadai capability generation --json
```

## netform-adapter

Versioned single-request local CLI/JSON bridge with a standalone Rust client.

Evidence level: `protocol_integration_not_gui_wiring`. Evidence: `integrations/netform-client/README.md`.

Input contract: `netform.kicadai.request.v1`.

Supported bounds:

- 64 KiB request, 2 MiB response; catalog search <=100 results; fixed method allowlist
- Catalog, pin-map lookup, read-only inspection, evidence integrity and board-family checking only

Required tools:

- KiCadAI binary; Rust 1.99 only to build the reference client, not to run the CLI protocol

Limits and acceptance requirements:

- No network service, provider or native tool execution; use a worker thread in a GUI
- NetForm GUI and live simulation engine remain separate and unchanged

```sh
kicadai --request ./examples/install-experience/adapter-request.json adapter
```

## numerical-conformance

Compare production Go MNA, independent equations, and optional ngspice.

Evidence level: `per_run_result_required`. Evidence: `report.json in each conformance bundle`.

Input contract: `kicadai.numerical-conformance.v1`.

Supported bounds:

- 12 frozen cases; 3-minute total / 15-second per external case; no retries
- DC/AC: 1e-8 V absolute + 1e-7 relative; transient: 1e-8 V + 0.5% relative

Required tools:

- none for analytical comparison
- ngspice exactly 47 for external conformance

Limits and acceptance requirements:

- Only ideal passive DC, AC and RC transient; no general solver certification
- Without --ngspice the external status is not_checked, never conformant

```sh
kicadai --output ./out/conformance conformance run
kicadai --ngspice /path/to/ngspice-47 --output ./out/external conformance run
```

## reproduction

Capture exact schematic input and first failing stage; replay offline.

Evidence level: `integrity_checked_not_attested`. Evidence: `reproduction.json and manifest.json`.

Input contract: `kicadai.reproduction.v1`.

Supported bounds:

- 64 KiB session input; one run; no retries or automated minimization
- Evidence: 256 files / 2 MiB each / 32 MiB total maximum

Required tools:

- none; native checks must be explicitly requested again

Limits and acceptance requirements:

- Only the confirmed schematic lane; conformance failures have their own replay command
- Never runs a command, path or SPICE input supplied by an untrusted package

```sh
kicadai --request ./session.json --output ./out/repro repro schematic
kicadai --target ./out/repro --output ./out/replayed repro replay
```
