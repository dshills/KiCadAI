# Closed-Loop Open-Set V7 Baseline and Adaptive-Round Protocol

Status: freeze candidate; execution prohibited until the V7 corpus freeze

## Admissible state

Execution begins from the V7 starting commit plus separately committed
contract, author packet, fresh corpus, selector, frontier, lineage, and
publication infrastructure. Every run binds the corpus manifest, authorship and
validator commitments, evaluator, synthesis policy, gap and transition policy,
adaptive selection policy, primitive inventory, catalog, model registry,
simulation environment, installed-KiCad promotion environment, and all prior
round seals.

Mismatch, uncommitted outcome-affecting bytes, missing evidence, an existing
retirement/final artifact, or an exceeded ceiling aborts before synthesis and
writes nothing.

## Generation-zero discovery baseline

1. Load exactly 18 discovery entries in immutable manifest order and strictly
   decode each behavior-only requirement. The exact count is a frozen corpus
   integrity property; invalid author files are corrected only in the bounded
   pre-publication window and are never dropped at evaluation time.
2. Run every case twice from isolated roots under identical seeds, inputs,
   ceilings, inventory, catalog, models, and environment. The harness fixes
   worker count, traversal order, random sources, locale, timezone, and
   floating-point mode; every routing, simulation, and other outcome-affecting
   subprocess runs single-threaded. Replays are compared only inside
   one exact environment manifest binding operating system, hardware
   architecture, CPU feature set, Go toolchain, runtime, KiCad, and solver
   versions; V7 does not claim cross-platform byte identity.
3. Require byte-identical complete exported synthesis evidence.
4. Promote every synthesis pass twice through clean installed-KiCad roots and
   require clean ERC, strict DRC, connectivity, route completion, writer,
   workflow, simulation, and zero round-trip-diff evidence.
5. Observe and aggregate with the frozen realizability-aware evaluator.
6. Preserve complete normalized root, suppressed, and candidate gap evidence,
   causal-suppression edges, and transition classifications.
7. Construct the generation-zero active cohort and deterministic bundle
   decisions from discovery evidence only.
8. Freeze rank one, exact members, cohort, required evidence, executable plan,
   input-frontier hash, and every environment commitment.
9. Atomically publish per-case evidence, aggregate, frontier graph, all
   decisions, selection, plan, checksums, and audit.

No held-out source, outcome, gap, diagnostic, frontier, lineage, or membership
may be opened or consulted.

## Untouched held-out baseline

After generation-zero selection is committed and before round-one
implementation, an isolated custodian evaluates all 18 held-out cases through
the identical replay and promotion path. Source and baseline payloads use
distinct fresh external 0600 keys and authenticated length-delimited metadata.
The repository receives only ciphertext, counts, hashes, algorithm metadata,
and policy commitments.

Here and below, `0600` is the required Unix permission mode of each external
key file: readable and writable only by its owner. It is not a key length or
algorithm identifier. Preflight must prove local POSIX ownership and permission
enforcement on the backing filesystem; if it cannot, file storage is prohibited
and an admitted OS credential store, KMS, or HSM is mandatory.

Every source, baseline, and final key is a distinct 32-byte value generated by
the operating system CSPRNG. Keys are created atomically with no-replace
semantics outside the repository, never accepted through command arguments or
environment variables, never logged, and opened only by the assigned custodian.
Persistent key files reside under a dedicated least-privilege custodian
security principal that the implementation process cannot assume, in a
nonsynchronized owner directory on an encrypted volume excluded from repository
and workspace backups. Key creation, open, and deletion are audit logged. An OS
credential store, KMS, or HSM may replace the file only when it provides at
least the same separation, no-export access boundary, audit record, and atomic
role binding.
Plaintext and key buffers are cleared after use where the runtime permits it;
temporary plaintext is deleted only after authenticated publication succeeds.
AES-256-GCM uses a unique random 12-byte (96-bit) nonce per encrypted record and
authenticates the frozen length-delimited metadata.

The frozen threat boundary protects held-out material from the implementation
workspace, implementation process, ordinary same-host users, repository
artifacts, backups, logs, and human result inspection. Host-administrator,
kernel, hypervisor, physical-memory, or custodian-principal compromise is an
infrastructure breach that consumes the evaluation; V7 does not claim that a
software harness on the compromised host can preserve blindness.

## Round input and deterministic selection

Round one consumes generation zero. A later round consumes only the immediately
preceding committed round output. The input contains:

- the ordered active cohort;
- every active case's complete current root frontier;
- prior selected atoms and members;
- prior implementation and result hashes;
- admitted lineage edges; and
- remaining round, atom, and member budgets.

Candidate generation is the bounded deduplicated closure of unions of active
case frontier signatures. A candidate advances a case only when it covers the
case's complete current frontier. Reuse, minimality, size, domain, uniqueness,
and outcome constraints apply before ranking. Prior atoms are ineligible.
With exactly 18 discovery cases, the nonempty subset-union closure contains at
most 262,143 pre-deduplication bundles; the frozen 262,144 ceiling therefore
covers the complete construction without truncation.

Rank one is admitted only with one complete generic plan covering every atom
and member. Missing plans, candidate overflow, or no eligible bundle retire V7.
If multiple candidates tie across every semantic rank field, the selector
publishes the full co-rank-one set and chooses canonical bundle-key byte order
as an explicitly labeled deterministic fallback among equal-impact candidates.

## Round implementation seal

Only selected atoms and admitted plan-bound prerequisites may affect outcomes.
A prerequisite is admitted only when it was listed before implementation, is
required to compile or execute a selected capability or preserve a shared
invariant that capability touches, has no independent unselected outcome
effect, and maps every changed path to a selected exact member. A separable
feature, unrelated refactor, or unmapped change is rejected. The implementation
seal separates production from verification artifacts and records these
mappings.

The seal proves `no independent unselected outcome effect` mechanically: it
records reverse call-graph, registry, configuration-loader, catalog, model, and
data-reference edges for every prerequisite path; every outcome-affecting
consumer must be inside the selected capability or the explicitly named shared
invariant. Focused runtime tracing must reproduce that consumer set. An
unmapped consumer, dynamic lookup that cannot be bounded, or disagreement
between static and runtime evidence rejects the prerequisite.

Toolchain, policies, budgets, seeds, simulation environment, and promotion
environment must remain byte-bound to generation zero. Catalog, inventory, and
model deltas are admitted only for explicitly selected component/model
capabilities and only when the seal records exact before/after hashes and no
unmapped changes.

The exact staged implementation passes focused and full local regressions,
installed-KiCad protected fixtures, deterministic replay tests, and fail-closed
tests. Prism reviews the staged bytes; remediation is complete before the seal
and implementation commit.

The Prism record uses a frozen checklist: selected-scope mapping, genericity,
fixture prohibition, deterministic ordering, fail-closed behavior, security and
sensitive-data boundaries, regression coverage, performance bounds, and exact
seal completeness. Each finding receives one disposition: `remediated`,
`rejected_with_reproducible_evidence`, or `not_applicable_with_contract_cite`.
Every high or medium finding requires a recorded disposition before sealing.
Prism does not select capabilities, inspect held-out material, or determine
evaluation outcomes.

## Single round evaluation

Each committed round is evaluated exactly once:

1. rerun all 18 discovery cases twice under the frozen execution contract;
2. physically promote every pass twice from clean roots;
3. reproduce exact case sets and aggregate evidence;
4. compare every active case against its input frontier;
5. require all selected input members to disappear for every retained case;
6. require every removed nonselected gap to retain identity or traverse one
   admitted deterministic successor edge. An edge is admitted only when it
   preserves the same case, assertion/observation causal token, scope, and
   capability, moves to the same or a higher ordinal in the policy's frozen
   stage-order groups, and carries an equal or stronger required-evidence set.
   An unknown stage fails closed. An unrelated beneficial side effect is
   insufficient because it would make selected-bundle causality ambiguous;
7. require every retained nonpassing case to expose a nonempty canonical next
   frontier;
8. require advancement of at least two active cases across two domains;
9. require no pass regression or unsafe-to-pass transition; and
10. require only seal-bound environment transitions.

If strict total pass uplift and at least one new active-cohort pass occur, this
same result becomes final public admission and no further round is allowed.
Otherwise, if every intermediate gate passes and budgets remain, atomically
publish the next frontier and freeze the next selection. Any other result
permanently retires V7 before held-out access.

## Final public admission

Public success binds the complete ordered round chain and proves:

- strict total discovery pass-count improvement;
- at least one newly passing active causal-cohort case;
- exact unique case sets;
- no baseline or intermediate pass regression;
- no unsafe-to-pass transition;
- complete admitted lineage for all removed nonselected gaps;
- deterministic replay and complete simulation/physical/KiCad/writer/routing/
  connectivity/round-trip evidence; and
- immutable policies plus only capability-sealed catalog/model transitions.

Failure atomically retires V7. Corpus mutation, selection change, budget
increase, retry, tuning, or gate relaxation is prohibited.

## One-time blind final

After public admission, a clean-tree authorized custodian validates the ordered
chain and three distinct external 0600 key paths, then begins one logical
held-out source/baseline evaluation session. Success requires strict held-out
pass uplift, at least one newly passing case whose hidden blocker lineage is
covered by the selected ordered chain, exact case-set preservation, no
regression, no unsafe-to-pass transition, deterministic replay, and complete
physical evidence.

The custodian performs a read-only preflight before decrypting any record:
free-space,
toolchain, permission, clean-tree, output-path, and resource-ceiling checks. A
pre-reveal failure may be retried at most twice only when a signed audit proves
that no authenticated plaintext record or baseline payload was produced and no
evaluation began. The reveal boundary is the first successfully authenticated
plaintext record or baseline payload. Any interruption or infrastructure
failure after that boundary normally consumes the final. The only exception is
an automatic resume from an authenticated custodian checkpoint when all of the
following are proven: the failure is signed as hardware, operating-system, or
storage infrastructure failure; no human or implementation context observed
plaintext, outcomes, or diagnostics; completed case evidence is encrypted,
hash-chained, and immutable; the commit, toolchain, policy, keys, and budgets are
unchanged; and no completed case is reevaluated. The interrupted incomplete case
may restart from its original deterministic inputs. At most two such resumes are
allowed. Missing proof, changed state, result inspection, or a third failure
consumes the final without resume.

Success artifacts are atomic and no-replace. The only plaintext result fields
are total case count, baseline pass count, final pass count, pass uplift,
regression count, unsafe-to-pass count, and the boolean causal-chain,
deterministic-replay, and complete-physical-evidence gates. No domain, case,
outcome-bucket, gap, diagnostic, frontier, lineage, or timing breakdown is
permitted. A permitted checkpoint resume is part of the same logical session
and neither reopens nor reevaluates a completed record. Any terminal failure
after reveal writes only a non-revealing permanent audit with no outcome-derived
aggregate. Either terminal outcome consumes V7. Authoritative
evidence comes from the committed clean-tree local harness, self-hashed
artifacts, exact toolchain commitments, isolated replay roots, and external-key
custodian attestations. GitHub Actions may run automatically after push as a
non-authoritative regression signal; they are not manually dispatched or
awaited by the protocol.
