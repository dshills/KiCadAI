# Closed-Loop Open-Set Capability Expansion V8 Plan

## Phase 0: Contract and executable semantics freeze

- Commit the V8 specification addendum, corpus rules, baseline protocol,
  selection policy, contract hash manifest, and verifier together.
- Implement and test obligation-anchor encoding, append-only causal paths,
  bounded fan-out, effect-closure accounting, exact semantic ranking, round
  progress, retirement, and terminal-state rules before corpus synthesis.
- Bind the public V7 retirement object and require `held_out_opened=false`.

Exit: every contract artifact is self-consistent, byte-frozen, locally tested,
and Prism-reviewed with all high/medium findings disposed.

## Phase 1: Fresh author packets and isolated corpus

- Create six checksum-bound author packets from only the frozen public behavior
  contract and one assignment each.
- Dispatch six isolated authors in fresh contexts. Each authors exactly three
  discovery and three held-out requirements in its designated empty quarantine.
- Permit at most two fresh replacements per assignment. Corrections are limited
  to packet-contract violations found without synthesis or outcome inspection.
- Validate syntax, schema, references, quotas, semantic diversity, exact paths,
  authorship provenance, packet hashes, and full-byte source hashes.

Exit: six independently authored valid bundles with no cross-author disclosure.

## Phase 2: Corpus adjudication and encrypted publication

- Adjudicate only public electrical/schema meaning without synthesis,
  feasibility, capability classification, or outcome inspection.
- Derive immutable obligation anchors and reject duplicates or broken semantic
  references.
- Atomically publish the 18 discovery requirements and encrypt the 18 held-out
  records with a fresh external 0600 V8 source key.
- Verify authenticated ciphertext, commitments, exact counts, and removal of
  superseded plaintext quarantines.

Exit: one immutable V8 corpus manifest with public discovery and encrypted
held-out halves; no held-out content has reached the implementation context.

## Phase 3: Generation-zero public and blind baselines

- Freeze the exact evaluator, gap registry, selector, toolchain, inventory,
  catalog, model registry, synthesis policy, promotion environment, seeds, and
  resource ceilings.
- Run all 18 discovery cases twice and promote every pass twice with installed
  KiCad from clean roots.
- Publish outcome buckets, complete obligation-anchored root frontiers, clusters,
  semantic co-rank-one candidates, selected bundle, effect-closure plan, and
  complete self-hashed evidence.
- In a separate custodian, evaluate all 18 held-out cases once under the same
  frozen selection boundary and publish only encrypted baseline evidence plus
  non-revealing aggregate commitments using a distinct external 0600 key.

Exit: reproducible generation-zero public selection and blind held-out baseline;
implementation has not accessed held-out content or outcomes.

## Phase 4: Selected generic implementation

- Prove and freeze the selected bundle's bounded effect closure before editing
  production behavior.
- Write one complete generic implementation plan mapping each path to a selected
  or closure member and rejecting any independent unselected effect.
- Implement only those capabilities. Do not add corpus IDs, family templates,
  coordinates, allowlists, expected outcomes, or unselected catalog/models.
- Add representative, adversarial, boundary, replay, closure, causal-path, and
  fail-closed tests.
- Run focused and full local tests, lint, installed-KiCad protected fixtures,
  historical public evidence projections, and deterministic seal reproduction.
- Prism-review the exact staged diff, remediate, self-hash, commit, and push.

Exit: one committed implementation seal bound to the frozen selection and plan.

## Phase 5: Bounded public discovery rounds

- Evaluate each committed round exactly once across all 18 discovery cases,
  with two synthesis replays and two physical promotions for every pass.
- Reconstruct immutable obligation anchors and validate append-only causal paths.
- Require changed gaps to be selected or in the predeclared effect closure;
  require unchanged gaps to remain byte-identical.
- Publish exactly one of: final public admission, an admitted next frontier plus
  frozen next selection, or permanent public retirement.
- Continue for at most three rounds and stop at the first strict public pass
  uplift with a newly passing active-cohort case.

Exit: committed public admission or terminal public retirement.

## Phase 6: One-time blind held-out final

- Proceed only after final public admission and a clean-tree preflight.
- Use separate external 0600 source, baseline, and final-result keys through the
  least-privilege custodian; never expose key material in arguments, environment,
  repository, logs, or implementation context.
- Evaluate the exact 18-case held-out set under the committed ordered capability
  chain, deterministic replay, and installed-KiCad physical gates.
- Publish encrypted per-case evidence and only non-revealing aggregate results.
- Require strict pass uplift, one newly passing lineage-covered case, no
  regression, no unsafe-to-pass transition, and exact case preservation.

Exit: committed encrypted held-out admission or consumed-final retirement.

## Phase 7: Documentation and terminal audit

- Update project status and README with the proven coverage boundary, selected
  generic capabilities, non-capabilities, and terminal V8 state.
- Audit every V8 requirement against committed artifacts and local verifier
  output. Preserve external keys according to the frozen retention policy.
- Prism-review documentation changes, commit, and push. Do not manually run
  GitHub Actions; hosted failures are repaired only if later reported.
