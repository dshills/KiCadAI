# Closed-Loop Open-Set Capability Expansion V3 Plan

Status: freeze candidate

## Phase 0: Contract freeze

- Review and commit the V3 addendum, corpus rules, baseline protocol, exact
  policy-v2/impact-registry contract, and checksums.
- Make no outcome-changing production edit after the starting checkpoint.

## Phase 1: Independent corpus freeze

- Provide only the allowed public authoring packet to a context-isolated author.
- Receive candidate files in quarantine.
- Run mechanical schema, neutrality, provenance, uniqueness, non-overlap,
  quota, acceptance, and structural-diversity checks.
- Copy passing bytes unchanged into the versioned corpus and commit manifest
  hashes before synthesis.

## Phase 2: Discovery baseline and selection

- Run all discovery cases twice under the frozen policy.
- Promote any baseline passes through two clean installed-KiCad roots.
- Observe and aggregate with capability-feedback policy v2.
- Seal the complete rank ordering and rank-one expansion plan.

## Phase 3: Held-out baseline seal

- Produce authenticated encrypted held-out baseline evidence without revealing
  case content or outcomes.
- Commit ciphertext and non-sensitive commitments only.

## Phase 4: Selected capability

- Implement only the sealed rank-one generic capability and inseparable
  prerequisites.
- Add generic representative, boundary, adversarial, deterministic replay, and
  fail-closed tests.
- Seal the reviewed production diff before held-out validation.

## Phase 5: Validation and release

- Prove strict discovery and selected-cluster uplift first.
- Run the one-time blind held-out comparison only after discovery succeeds.
- Require strict held-out uplift and every preservation/promotion gate.
- Run the complete applicable local regression and installed-KiCad suites.
- Review staged changes with Prism, remediate, commit, and push.
- Do not manually start or inspect GitHub Actions.
