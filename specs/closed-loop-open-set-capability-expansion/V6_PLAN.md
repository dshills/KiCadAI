# Closed-Loop Open-Set Capability Expansion V6 Plan

Status: freeze candidate

## Phase 0: Contract and selector freeze

- Commit this addendum, plan, corpus rules, baseline protocol, selection policy,
  adversarial contract tests, and checksum manifest.
- Bind the V6 starting commit and inherited evaluator, impact, synthesis,
  transition, inventory, catalog, model, environment, and historical-retirement
  commitments.
- Prove exact member identity, full-blocker coverage, minimality, reuse floors,
  eligibility, deterministic ranking, tie failure, complete-plan admission,
  exact selected-member removal, and held-out non-influence.
- Prohibit corpus authoring and synthesis until the freeze commit exists.

## Phase 1: Fresh three-author corpus freeze

- Give three context-isolated authors only the committed public packet and
  disjoint assignments.
- Receive each bundle into a separate quarantine inaccessible to the other
  authors and implementation context.
- Mechanically validate strict schema, vocabulary, references, bounds,
  acceptance, provenance, quotas, diversity, cross-author uniqueness, and
  V1-V5 historical non-overlap without synthesis.
- Encrypt held-out sources with a fresh external key and atomically publish the
  canonical corpus and commitments.

## Phase 2: Discovery baseline and causal selection

- Run all 18 discovery cases twice from isolated roots under frozen limits.
- Require exact replay equality and two clean-root installed-KiCad promotions
  for every pass.
- Preserve complete typed root-blocker sets, build bounded minimal causal-unlock
  bundles, and publish all eligible and ineligible candidates with reasons.
- Freeze rank one, claimed unlock cases, exact members, required evidence, and
  one complete executable generic plan.

## Phase 3: Held-out baseline seal

- After selection is committed, evaluate all 18 held-out cases through the
  identical replay and promotion path.
- Encrypt source and baseline payloads with distinct external 0600 keys.
- Publish only authenticated ciphertext, counts, commitments, algorithm
  metadata, and non-revealing audit evidence.

## Phase 4: Selected generic bundle

- Implement only the frozen selected bundle and plan-bound generic
  prerequisites.
- Add representative, adversarial, boundary, replay, and fail-closed tests with
  no V6 identities or circuit-family special cases.
- Preserve the full local suite and installed-KiCad protected fixtures.
- Prism-review and remediate the exact staged implementation, then seal and
  commit its bytes before any final evaluation.

## Phase 5: Public admission

- Rerun discovery from the sealed implementation.
- Require strict total and claimed-unlock pass uplift plus every preservation,
  deterministic, physical, installed-KiCad, writer, routing, connectivity, and
  round-trip gate.
- Atomically publish success evidence or permanently retire V6 without opening
  held-out material.

## Phase 6: One-time blind final

- Recheck a clean sealed tree and three distinct external key paths.
- Run the blind held-out comparison exactly once.
- Require strict held-out uplift and the sealed complete-blocker causal boolean.
- Atomically publish encrypted success evidence and aggregates, or only a
  non-revealing permanent failure audit.
- Prism-review only non-sensitive staged evidence, commit, and push. Do not
  manually run or inspect GitHub Actions.
