# Closed-Loop Open-Set Capability Expansion V5 Plan

Status: freeze candidate

## Phase 0: Contract freeze

- Commit this addendum, plan, corpus rules, baseline protocol, machine-readable
  selection policy, contract tests, and contract checksum.
- Bind the starting commit and inherited public policy bytes.
- Prove package grouping, eligibility, deterministic ranking, exact selected-
  member gap removal, and historical held-out retirement adversarially.
- Prohibit corpus authoring and synthesis until the freeze commit exists.

## Phase 1: Three-author corpus freeze

- Give three context-isolated authors only the committed public packet.
- Receive each author's files into a separate quarantine inaccessible to the
  other authors and implementation context.
- Mechanically validate schema, vocabulary, references, bounds, acceptance,
  provenance, quotas, diversity, cross-author uniqueness, and historical
  non-overlap without synthesis.
- Encrypt held-out sources, freeze all commitments and manifest order, and
  commit the corpus separately from the contract.

## Phase 2: Discovery baseline and package selection

- Run all 18 discovery cases twice from isolated roots under frozen limits.
- Require byte-identical normalized evidence and two clean-root installed-
  KiCad promotions for every baseline pass.
- Aggregate exact typed root-gap clusters, then form eligible capability
  packages under `V5_SELECTION_POLICY.json`.
- Atomically freeze the complete package ranking, selected members, affected
  cases/domains, required evidence, and executable generic plan.

## Phase 3: Held-out baseline seal

- Evaluate all 18 held-out cases through the identical deterministic and
  promotion path only after selection is committed.
- Encrypt source and baseline payloads with separate external keys.
- Expose only commitments, counts, policy hashes, and ciphertext; disclose no
  held-out requirement, outcome, gap, diagnostic, or package membership.

## Phase 4: Selected generic package

- Implement only the frozen selected package and inseparable generic
  prerequisites.
- Add representative, adversarial, boundary, replay, and fail-closed tests with
  no V5 identities or circuit-family special cases.
- Preserve the full local suite and installed-KiCad protected fixtures.
- Prism-review and remediate the staged implementation, then seal exact reviewed
  bytes and commit before any final evaluation.

## Phase 5: Public admission

- Rerun discovery from the sealed implementation.
- Require strict total and selected-package uplift plus every preservation,
  deterministic, physical, KiCad, and round-trip gate.
- If public admission fails, retire V5 without opening held-out material.

## Phase 6: One-time blind final

- Recheck a clean sealed tree and distinct external key paths.
- Run the blind held-out final exactly once.
- Require strict held-out uplift and the sealed selected-package causal boolean.
- Atomically publish complete success artifacts, or only a non-revealing
  permanent failure audit.
- Prism-review only non-sensitive staged evidence, commit, and push. Do not
  manually run or inspect GitHub Actions.
