# V10 Baseline, Exposure, and Adaptive Evaluation Protocol

V10 adopts V9's generation-zero evidence, typed root-path, complete effect-
exposure, ranking, causal successor, preservation, retirement, and blind-final
semantics with version-separated schemas and artifacts. This file records the
V10-specific preconditions and non-negotiable execution bounds.

Evaluation requires a clean committed tree; authenticated 24/24 corpus;
checksum-frozen evaluator, evidence validator, public publisher, exposure
engine, and blind publisher; absent V10 output paths; and the committed V9
prepublication retirement. The assignment-feasibility proof and authenticated
corpus publication are mandatory bindings.

All 24 discovery cases run in manifest order twice in independent clean roots.
Exports, diagnostics, inventories, observations, frontiers, and hashes match
byte-for-byte. Every pass satisfies all 14 gates and receives two additional
distinct clean-root installed-KiCad promotions. Every case is exactly `pass`,
`unsupported`, `unsafe`, or `exhausted`; every eligible nonpass has at least one
complete typed root path in topology, component, model, simulation,
physical_design, or verification.

Complete candidate enumeration is fail-closed on overflow. Selection commits
fully covered cases, every effect-exposed case, selected/closure path hashes,
all nonselected sibling path hashes, and every non-exposed case hash. Ranking
orders unlock count, reporting-domain count, circuit-role count, and safety
weight descending, then exposed-noncovered count, sibling burden, atom count,
and member count ascending. Canonical identity breaks only a full semantic tie.

Per round: at most three atoms, nine members, and four same-anchor successors.
Cumulative: at most two rounds, six atoms, and 18 members. A round must advance
at least two active cases across two domains and two circuit roles. Selected
paths disappear only on satisfied obligation or append one nonweaker same-
anchor successor; siblings remain byte-identical; non-exposed cases remain
byte-identical; baseline passes do not regress; unsafe does not become pass.

Strict total public pass uplift plus one new active-cohort pass admits public
validation. Otherwise only a mechanically admissible advance may continue to
a separately frozen second selection; every other state retires V10.

After public selection and before implementation, an isolated custodian opens
the V10 source key and creates a distinct baseline key to evaluate all 24 held-
out cases under generation zero. Only encrypted per-case records and frozen
non-revealing aggregates are published. A final held-out run is authorized only
after public admission and uses a third distinct key. It requires strict pass
uplift attributable to the public selected chain, no regressions, deterministic
replay, exact preservation, and full physical promotion.

All baseline, selection, round, retirement, and final destinations are fresh,
same-parent staged, synchronized, checksum-verified, and atomically installed
without replacement. There is no retry, corpus mutation, expected-result edit,
manual rank override, budget increase, gate relaxation, fixture-specific
implementation, held-out disclosure, or manual GitHub Actions run.
