# Closed-Loop Open-Set Capability Expansion Plan

Status: version-1 contract frozen; implementation active

## Phase 0 — Contract And Existing-System Audit

- Map the current behavioral-intent evaluator, capability-impact registry,
  capability-expansion planner, open-topology synthesis report, physical
  promotion report, and installed-KiCad evidence contracts.
- Record which fields are authoritative and which existing gaps are only prose.
- Freeze the outcome, gap-scope, cluster-key, ranking, and improvement policy.
- Add this specification, corpus rules, baseline protocol, and plan.

Exit gate: the new milestone extends existing contracts without creating a
parallel success or promotion path.

## Phase 1 — Evidence Adapter And Aggregate Report

- Define a versioned open-set synthesis observation/report schema.
- Adapt normal open-topology synthesis and physical-promotion evidence into the
  four terminal outcomes and seven gap scopes.
- Preserve earliest root cause, independent blockers, downstream symptoms,
  consumption, requirement paths, and raw evidence hashes.
- Extend deterministic clustering/ranking to current synthesis stages.
- Produce an aggregate rank-1 expansion plan through
  `internal/capabilityexpansion`.
- Add strict codec, normalization, replay, reorder, corruption, and
  identity-neutrality tests.

Exit gate: synthetic identity-neutral cases prove deterministic classification,
causal suppression, clustering, ranking, and planning without corpus knowledge.

## Phase 2 — Independent Corpus Authoring And Freeze

- Author 12 discovery and 12 held-out behavior-only requirements under the
  normative corpus rules.
- Ensure each role has two analog, power, digital/control, MCU/interface,
  sensor, and mixed-signal cases.
- Validate behavioral neutrality, source independence, domain coverage, safety
  declarations, role separation, and absence of implementation nouns.
- Freeze manifest order, file bytes, hashes, policy, impact registry, budgets,
  and environment contract.
- Commit the corpus freeze before recording production outcomes.

Exit gate: corpus mutation, reorder, duplication, role leakage, implementation
language, or hash drift fails tests.

## Phase 3 — Untouched Baseline And Selection Seal

- Run every case twice through the normal synthesis path.
- Run physical promotion only for baseline `pass` cases.
- Require byte-identical per-case evidence and aggregate reports.
- Classify every case as `pass`, `unsupported`, `unsafe`, or `exhausted`.
- Freeze the ranked discovery clusters and seal rank 1 before revealing held-out
  cluster membership to implementation work.
- Write the aggregate expansion plan and baseline checksums.
- Commit the untouched baseline separately.

Exit gate: the checked-in baseline reproduces exactly from the frozen corpus,
policy, registry, budgets, and toolchain contract.

## Phase 4 — Rank-1 Capability Expansion

- Gather only the reviewed sources and generic prerequisites required by rank 1.
- Build a quarantined candidate through the existing capability-expansion
  contracts when registry content is required.
- Implement generic topology, component, model, simulation, physical, routing,
  or verification support selected by the evidence.
- Add representative, boundary, adversarial, reorder, replay, and fail-closed
  tests before changing expected corpus outcomes.
- Do not work around unavailable rank-1 evidence by selecting an easier cluster.

Exit gate: focused tests prove reusable capability behavior without referencing
corpus identities, paths, hashes, coordinates, or expected results.

## Phase 5 — Closed-Loop Rerun And Improvement Proof

- Rerun identical discovery and held-out corpus bytes with unchanged policies,
  gates, and budgets.
- Verify strict discovery and held-out pass-count improvement.
- Verify rank-1 causal uplift and no baseline-pass regression.
- Verify unsafe cases remain fail closed unless new reviewed safety evidence
  directly resolves the blocker.
- Verify remaining cluster identities and report bytes are deterministic.
- Generate final report, comparison, selection attribution, and checksums.

Exit gate: the improvement verifier proves the specification’s complete
baseline-to-final contract.

## Phase 6 — Electrical And Physical Promotion

- Promote every newly passing case twice from clean roots.
- Require all applicable trusted analyses, corners, fault, thermal, SOA, and
  isolation evidence.
- Require readable hierarchy, deterministic multilayer placement/routing,
  connectivity, route completion, writer correctness, installed-KiCad ERC and
  strict DRC, zero round-trip differences, and identical project bytes.
- Build the promotion matrix and any review-ready capability bundle.

Exit gate: all new pass claims have full local KiCad-backed evidence.

## Phase 7 — Preservation, Audit, Review, And Release

- Run affected focused tests after each correction and the complete local suite
  before closeout.
- Preserve all earlier frozen synthesis and protected fixture evidence.
- Scan production code for corpus identities and prohibited shortcuts.
- Write the completion audit and update README, project status, and roadmap.
- Stage the complete diff, run Prism, remediate or directly disprove every high
  and medium finding, and rerun affected tests.
- Commit and push. Do not manually run or monitor GitHub Actions.

Exit gate: clean pushed worktree, reproducible artifacts, and a
requirement-by-requirement completion audit.
