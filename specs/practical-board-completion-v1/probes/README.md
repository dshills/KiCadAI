# Non-reserved requirement probes — not AI outputs

These six human-authored development specifications retain the original P01–P06 briefs and acceptance text beside a topology-neutral structured probe. They are not recovered provider proposals, accepted live outputs, complete clause coverage certificates, or new benchmark successes. No P07/P08 probe exists. The original eight-case denominator is unchanged.

The probe vocabulary deliberately states required behavior even where the current catalog provider has no consumer for it. For example, combined sensor measurements are separate required facts, reverse-input survival is not mislabeled as an ordinary voltage clamp, ADC acquisition must come from the selected controller, and a pushbutton must not be fabricated from an unrelated supported function. A JSON-shape validation pass does **not** prove these named constraints are enforced. Admission requires a separate consumer/evidence mapping; unknown or ignored clauses fail it. Failure of these probes cannot prove that every possible faithful encoding fails.

The input JSON supplies no selected part, pin, netlist, component value, placement, route, expected output or additional clock-stray/ADC acquisition fact. Functional interface relationships are authored assistance. The 64-component limit is the existing v3 engine policy, not a claimed user constraint. All common physical and electrical clauses still require independent checks, including perimeter access, layer count, startup and temperature/tolerance corners. These boolean requirement facts do not themselves provide those checks.

Authoring checks before development are retained under `.cache/practical-board-completion-v1/preparation/`. The first six shape validations rejected common-return bindings because the current explicit-reference validator discarded a common return for side-named roles. A separate red/green regression reproduces and fixes that production defect. For the eventual **same-byte** baseline/candidate probes, the new optional `reference_domain` field is omitted from both: each probe declares exactly one ground domain and every interface has the corresponding physical common-return binding. Both source versions support this unambiguous legacy encoding. This is an authoring-time serialization choice, not a baseline-only patch, weakened return constraint, or qualifying engine uplift. Earlier bytes remain in the preparation receipts.

P04's auxiliary output is bound directly to its requested output connector during authoring; it is not left as an unconnected semantic port. The first direct-output spelling (`aux_power`) was rejected by both decoders; the documented `port:aux_power` form is used before freezing the development inputs. This endpoint extension is absent in the original baseline. Its baseline decoding rejection is a **protocol incompatibility**, never a qualifying engine improvement. The other five probes use the shared legacy encoding. Any further authoring corrections must occur before the first immutable development manifest. Once a development batch starts, these bytes cannot be adjusted to match observed generation results.

During this task the shared historical FEASIBILITY document was read, including its already-public reserved-case summaries. No reserved input was decoded, compiled, used as a probe, or used to select an implementation change. Reserved results must still be labeled public-frozen, not blind.
